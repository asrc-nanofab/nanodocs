# AGENTS.md — how this repo behaves

Guide for coding agents working in this repo. The [README](README.md) is the
human-oriented overview; this file is the operational contract. When they
disagree, this file and `.cursor/rules/` win.

## What this is

A Zensical site (modern theme) on **Cloudflare Pages**
(`https://nanodocs.pages.dev`) whose content is **synced from Google Docs**.
Staff write SOPs/policies as Google Docs; the Nanodocs Registry sheet lists what
gets published; `scripts/sync_gdocs.py` converts each doc to a site page.
This repo is a rendering of the docs, not the source of truth.

```text
Google Docs ──> Nanodocs Registry ──> scripts/sync_gdocs.py ──> docs/**/*.md
                                                          ├─> docs/**/img/          (extracted images)
                                                          └─> docs/assets/pdfs/     (local PDFs)
docs/ ──> zensical build ──> site/ (then rm site/assets/pdfs) ──> Cloudflare Pages
docs/assets/pdfs/ ──> wrangler r2 object put --remote ──> R2 nanodocs-pdfs
/assets/pdfs/* ──> functions/assets/pdfs/[[path]].js ──> env.PDFS (R2)
```

Pages has a **25 MiB per-file** limit. PDFs stay on disk for `zensical serve`
and `--strict`; production serves them from the private R2 bucket
`nanodocs-pdfs` via the `PDFS` binding. Do not put PDFs in the Pages
artifact.

## Hard rules

1. **Never run `git commit`, `push`, `tag`, or `amend`.** The user commits.
   Suggest commit messages when asked.
2. **Never hand-edit generated content.** That is:
   - any page starting with `<!-- AUTO-GENERATED by scripts/sync_gdocs.py ... -->`
   - anything under `docs/**/img/` or `docs/assets/pdfs/`

   To change these, fix the source Google Doc, the registry sheet, or the sync
   script — then re-run the sync. Hand edits are silently overwritten.
3. **Verification gates.** After Python changes: `uv run ruff check .` and
   `uv run ruff format .`. After any docs/config change:
   `uv run zensical build --strict` must pass (it validates all internal links).
4. **Dependencies via `uv` only** (`uv add`, `uv add --group dev`). Never raw pip.

## Commands

```bash
uv run python scripts/sync_gdocs.py                      # every public document
uv run python scripts/sync_gdocs.py --group deposition
uv run python scripts/sync_gdocs.py --asset pecvd --only SOP
uv run zensical serve                                    # http://127.0.0.1:8000/
uv run zensical build --strict                           # required gate
# After a PDF changes, upload that key to R2 (user-run; --remote is required).
# The key is the page path with a .pdf suffix:
npx wrangler r2 object put nanodocs-pdfs/tools/deposition/pecvd/sop.pdf \
  --file=docs/assets/pdfs/tools/deposition/pecvd/sop.pdf \
  --content-type=application/pdf --remote
```

A push to `main` deploys Pages. Cloudflare build command:
`zensical build --strict && rm -rf site/assets/pdfs`. Binding and bucket are
in `wrangler.jsonc` (`PDFS` → `nanodocs-pdfs`).

The sync needs network access to `docs.google.com` (sandboxes may need full
network). No credentials: all docs/sheets are "anyone with link can view".

## How the sync maps docs to pages

Defined in `scripts/sync_gdocs.py`. One workbook (Nanodocs Registry,
`REGISTRY_ID`) with three tabs (`REGISTRY_GIDS`: `groups`, `assets`,
`documents`).

- An **asset** is a tool or hood. `id` is the permanent URL segment;
  `name` is the sidebar label. An asset with a published document is a
  directory. Its `index.md` is generated from the asset row (name, and
  description / manufacturer / model when filled) and is not a Google Doc.
- A **document** is one Google Doc. `label` is the sidebar text and the
  file is `slugify(label).md` (hyphens). `title` is the H1. `audience`
  `public` is what this build publishes. A blank `doc` cell is unpublished.
- A **group** says what the asset is and, through `section`, which tab it
  appears on. Hoods are assets in `wet-processing`, whose section is
  `chemicals`.

```text
docs/<section>/<group>/<asset>/index.md
docs/<section>/<group>/<asset>/<slug>.md     # asset set
docs/<section>/<slug>.md                     # no asset, section set (policy)
docs/<slug>.md                               # no asset, section blank (signup)
```

`id` is permanent. A `label` edit moves the page; the sync records the
doc's last path in `.sync-state.json` and appends the old URL to
`docs/_redirects`. The PDF key is that same path under
`docs/assets/pdfs/`. Unknown columns are ignored.

Sidebar order lives in `.nav.yml`. The sync relabels entries it generated,
appends a missing page at the end, and does not reorder or remove. It
creates `<asset dir>/.nav.yml` (`index.md` first, then each document) and
never opens `docs/.nav.yml`. A stale entry whose page moved fails
`zensical build --strict` until the line is deleted.

Keep `mkdocs.yml`. Do not add `zensical.toml` until they ship a
conversion tool. The on-page H1 of a document is the sheet `title`.

## Google export quirks (debugging rendering issues)

The script compensates for known Google Docs → Markdown export behaviors. If a
synced page renders oddly, check against this list before changing the script:

| Quirk | Handling |
| --- | --- |
| Images downscaled to ~640 px | Originals recovered from the DOCX export by aspect+pixel matching; author's display size kept via `{ width="…" }` |
| "Wrap text" / "Break text" images silently dropped | Cannot be fixed in the script — sync prints a warning; the doc author must set "In line with text" |
| Inline TOC exported in many shapes (plain, bold, heading-styled label; entries with resolved or `#heading=` anchors, tab + page numbers) | Stripped by `TOC_LABEL_RE`, `TOC_ENTRY_RE`, `TOC_PAGENUM_RE` |
| Letterhead logo + doc title at top | Stripped; the page supplies its own H1 |
| Empty heading lines (styling leftovers) | Stripped |
| Headings indented inside lists render as literal text / code blocks | Dedented by `_dedent_nested_headings` |
| Nested list items indented by parent marker width (2–4 spaces); Python-Markdown needs 4 per level, so lists render flat | Re-indented by `_normalize_list_indent` |
| Body sections authored as Heading 1 become siblings of the page's H1 title, emptying the sidebar TOC | All headings demoted one level by `_demote_body_headings` when a body H1 exists |
| "AI-generated content may be incorrect" alt-text boilerplate | Stripped |

Image files are content-hash named, so re-syncs are idempotent and identical
images dedupe. Stale images from previous syncs may linger in `img/` dirs;
they're harmless but can be deleted if unreferenced.

## Repo map

| Path | What it is |
| --- | --- |
| `docs/` | Site content — generated pages plus hand-written indexes, `faq/`, `signup/`, `authoring/` |
| `docs/assets/pdfs/` | Local PDFs (sync output). Production copies live in R2. |
| `functions/assets/pdfs/` | Pages Function proxying `/assets/pdfs/*` to R2 |
| `wrangler.jsonc` | Pages + R2 binding (`PDFS`) |
| `scripts/sync_gdocs.py` | The sync (single source of sync behavior) |
| `docs/robots.txt`, `docs/google*.html` | Search Console / crawlers; do not delete the google HTML file |
| `mkdocs.yml` | Site config (Zensical modern; `site_url` is `https://nanodocs.pages.dev`). Sidebar order lives in `docs/**/.nav.yml`. |
| `overrides/` | Theme extras: PDF-link pills; slate `--md-default-bg-color` lift only |
| `plans/` | Dated, phased work plans with review gates (see `.cursor/rules/plan-files.mdc`) |
| `.cursor/rules/`, `.cursor/commands/` | Agent guardrails and workflows |

## Conventions

- Multi-phase work gets a plan file in `plans/` (`YYYY-MM-DD-slug.md`) and is
  executed phase by phase with user approval between phases.
- Comments explain *why*, not *what*. DRY; no dead code or speculative options.
- The site is served at the **domain root** (`https://nanodocs.pages.dev/`,
  local `http://127.0.0.1:8000/`). Always use relative links in content.
  Absolute `/nanodocs/…` paths are leftovers from GitHub project pages.
