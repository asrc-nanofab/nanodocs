# Updating a single Google Doc on the site

Personal runbook. The source of truth is the Google Doc, not the markdown
in this repo. `scripts/sync_gdocs.py` never uploads to R2. A push to
`main` deploys the HTML page via Cloudflare Pages. The PDF is a separate
manual put into the `nanodocs-pdfs` bucket.

Worked through 2026-08-24 on **Becoming a Nanofab User** (`docs/signup.md`).
The steps below are the generic version for any registered doc.

## What actually happens

```text
Edit Google Doc
    → sync script writes local markdown + images + PDF
    → wrangler r2 object put --remote  (PDF, live immediately)
    → git commit + push main           (page, live after Pages build)
```

Do **not** hand-edit a page that starts with
`<!-- AUTO-GENERATED by scripts/sync_gdocs.py -->`. The next sync
overwrites it.

## 1. Edit the Google Doc

Change the shared Google Doc and let it save. Sharing stays
"anyone with the link can view" — the sync has no credentials.

Images must be **In line with text**. Wrap/Break text images are
silently dropped by Google's Markdown export.

## 2. Sync only that document

`--only` is an **exact** match on the registry sheet name
(`Tool Name` for tools, `Document Name` for chem/policy). A typo or a
heading from inside the doc (`Getting Started`) will fail with
`No syncable documents matched.`

```bash
# one of:
uv run python scripts/sync_gdocs.py tools  --only "AJA Sputter"
uv run python scripts/sync_gdocs.py chem   --only "Chromium Etch SOP"
uv run python scripts/sync_gdocs.py policy --only "Becoming a Nanofab User"
```

Optional live loop while still editing the doc (pair with
`uv run zensical serve`):

```bash
uv run python scripts/sync_gdocs.py policy --only "Becoming a Nanofab User" --watch
```

A full `tools chem policy` run does the same work for every row. It
still does **not** talk to R2.

## 3. Check the page locally

```bash
uv run zensical serve            # http://127.0.0.1:8000/
uv run zensical build --strict   # must pass before you commit
```

Local View PDF reads `docs/assets/pdfs/` from disk. Production does not
— Pages deletes that folder in the build, then the Function serves the
same path from R2.

## 4. Upload the PDF to R2 (if it changed)

Keys match the local path under `docs/assets/pdfs/`:

| Section | Local file | R2 key |
| --- | --- | --- |
| tools | `docs/assets/pdfs/tools/<file>.pdf` | `nanodocs-pdfs/tools/<file>.pdf` |
| chem | `docs/assets/pdfs/chem/<file>.pdf` | `nanodocs-pdfs/chem/<file>.pdf` |
| policy | `docs/assets/pdfs/policy/<file>.pdf` | `nanodocs-pdfs/policy/<file>.pdf` |

```bash
npx wrangler r2 object put nanodocs-pdfs/policy/Becoming_a_Nanofab_User.pdf \
  --file=docs/assets/pdfs/policy/Becoming_a_Nanofab_User.pdf \
  --content-type=application/pdf --remote
```

`--remote` is required. Without it Wrangler writes a local emulator
under `.wrangler/` and the live site is unchanged.

Success looks like `Upload complete.` The live View/Download pills
pick up the new bytes immediately — Pages does not need a rebuild for
PDF content.

Skip this step if only the HTML page changed and the PDF export is
the same.

## 5. Commit and push `main`

The page is not live until `main` is pushed. Typical files:

- the generated markdown page
- the local PDF under `docs/assets/pdfs/` (keep it in git for
  `zensical serve` / `--strict`)
- any new images under `docs/**/img/`

```bash
git add docs/signup.md docs/assets/pdfs/policy/Becoming_a_Nanofab_User.pdf
git commit -m "Point Nanofab signup policy links at the Cloudflare Pages site"
git push origin main
```

Pages build command is `zensical build --strict && rm -rf site/assets/pdfs`.
Live site: `https://nanodocs.pages.dev/`.

## Name cheatsheet

Exact `--only` strings come from the registry sheets, not the on-site
H1. A few that are easy to get wrong:

| Sheet name (`--only`) | Section | Page |
| --- | --- | --- |
| `Becoming a Nanofab User` | policy | `docs/signup.md` |
| `Lab Manual` | policy | `docs/policy/manual.md` |
| `Safety Manual` | policy | `docs/policy/safety.md` |
| `Lab Suspension` | policy | `docs/policy/suspension.md` |
| `AJA Sputter` | tools | `docs/tool_sops/deposition/aja_sputter.md` |

Chem/policy docs also need a row in `CHEM_PAGE_MAP` / `POLICY_PAGE_MAP`
in `scripts/sync_gdocs.py` or the sync skips them. Tools are
slugified from the name unless they are in `TOOL_PAGE_OVERRIDES`.

## Wrangler permission error (`~/node_modules`)

`npx wrangler` from this repo walks up looking for a `node_modules`
to stash cache in. A leftover `~/package.json` + `~/node_modules`
(owned by `nobody`, from an accidental `npm install 18` in `$HOME`)
made it try:

```text
mkdir ~/node_modules/.cache/wrangler  →  EACCES
```

Auth had already succeeded; the R2 put never ran. Fix: delete that
home-directory junk (`sudo rm` if it is not yours), then retry the
put. Do not confuse it with `agent/node_modules` — that is the chat
Worker and is unrelated.

`--remote` vs that cache failure are different: one is "write to the
real bucket", the other is "Wrangler could not write its local cache
so it aborted".
